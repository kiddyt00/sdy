# archive/ —— 已停用的东西，留档可查

这里放**不再使用、但保留历史价值**的文件。与「删掉」的区别：随时能翻出来看当时怎么做的；
与「留在根目录」的区别：不干扰日常阅读。

> **这里的东西不要照着重跑**。它们依赖的环境、流程或约定可能早就变了。

## local-tools/ —— 腾讯文档同步工具链（2026-10-15 归档）

| 文件 | 原本干什么 |
| --- | --- |
| `pull_tencent_docs.py` | 从腾讯在线文档拉回最新内容，与上次推送快照比对 |
| `push_tencent_docs.py` | 把本地 docx 推送到腾讯在线文档 |
| `set_tencent_permission.py` | 推送后把在线文档设为「公开可编辑」 |
| `sync_docs_lib.py` | 上面几个脚本共用的腾讯文档 API 封装 |

**为什么归档**：用户 **m15454** 明确说「之前有个规则文档需要同步到腾讯文档，这个规则取消掉」，
`.agent_rules.md` 开头的规则 1–6（腾讯文档同步）据此整块作废。现在的口径是
**只维护仓库内的 `.md` / `.html`**，改完直接 commit + push，不再有拉取 / 转换 / 推送 / 设权限四步。

**为什么不是直接删**：它们曾真实用过（第 1–22 轮），`sync_docs_lib.py` 里对腾讯文档 openapi 的
调用方式有参考价值；且当时踩过的坑（导出配额每用户每天 9 次、导入会生成新文档导致链接变化）
在 `细节讨论记录.html` 里有记录，留个源码便于对照。

**根目录为什么还留着 `convert_html.py`**：老板 2026-10-15 明确指定保留。
注意它的方向是 **HTML → docx + md**（不是反过来），输出 docx 原本就是给推送用的；
现在只剩「把 HTML 导成 md/docx 给人看」这一个用途。它依赖 `.venv` 里的 `lxml` 与 `python-docx`。

**怎么恢复**：把需要的脚本 `git mv` 回根目录即可——它们仍在 git 跟踪中（归档 ≠ 移除出仓库）。
