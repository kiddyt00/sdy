牵牛花导出能力确认清单 Action item 0 · before M3 sync goes live

这份清单用于向牵牛花（服务商 / 客户经理 / 售后）确认数据能不能拿得出来、拿得全不全。 M3 的 CSV 对账工具已经就绪（对账工作台），只等确认导出字段即可对接真实文件。 确认方式：请对方导出一份真实文件发来，用「字段核对」一栏逐项打勾；拿不到的项目记录替代方案。

A导出能力（最关键的 3 问）

要确认的问题为什么问对方答复 / 截图
1. 商品与库存能否导出为 CSV / Excel？在后台哪个菜单？若只能看不能导 → 需要别的方案（截图录入 / 手工盘点） 导出是 M3 同步的前提；拿不到文件就只能纯手工维护
2. 是全量导出还是按条件/分页？有没有定时自动导出或开放 API？最好是「一键全量」；有 API 则可做定时自动同步 决定同步是「手工月度」还是「自动化」
3. 导出字段有哪些？请给一份真实样例文件（脱敏可）。直接决定本工具的字段映射表要不要改 对账引擎靠表头识别字段

C细节与坑

问题为什么答复
文件编码是 UTF-8 还是 GBK？Excel 打开会不会乱码？乱码会让整份文件报废
无条码商品怎么表示？（空列 / 内部编码 / 不导出）本工具会把无条码行记为「无效」并跳过，避免误对账
导出的是实时库存还是某个时点快照？决定对账差异算不算真差异
库存单位与销售单位是否一致？（整箱 vs 单瓶）单位不一致会把差异放大成千倍
能否导入库存调整？导入模板字段是什么？「库存回填 CSV」要靠导入回到牵牛花；不能导入则只能手动改
导出/导入是否有次数或时间限制？决定同步频率

D拿到样例文件后怎么验

  • 打开 对账工作台 → 选择该 CSV 文件（或整段粘贴）→ 点「开始对账」。
  • 看顶部「无码/无效」是否为 0；若很多，说明条码列没被识别，把实际列名告诉我，我改字段映射。
  • 差异数量是否合理：库存差异应集中在最近有动销的商品；如果几乎全表都是差异，多半是单位或快照时点问题。
  • 确认无误 → 勾选差异 → 导出「库存回填 CSV」→ 在牵牛花里导入（或按导入模板改名后导入）。
结论回填：拿到答复后，把「能不能自动拿数据」的结论记到《开发计划》依赖用户事项表（行动项 0）， 并决定 M3 是「手工月度对账」还是「自动化同步」。
