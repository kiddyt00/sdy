# web · 商城 Web 端（顾客端 + 管理端）

四人家庭超市的**手机浏览器商城**：熟客扫码或点链接就能下单，家里人用同一个仓库里的管理端看库存、改价、处理订单——不需要装 App，也不需要小程序审核。

后端在线时，规则与账目全部由 Go 服务端执行；后端不在时自动降级为「本地演示」，只用浏览器 localStorage，页面照常能点。

## 本地运行

无构建步骤、无 npm 依赖，起一个静态服务就行。

### 方式 A：纯前端演示（无后端）

```bash
cd /home/kiddyt00/GolandProjects/sdy    # 注意：从仓库根起服务，不要 cd 进 web/
python3 -m http.server 8910
```

- 顾客端：<http://127.0.0.1:8910/web/index.html>
- 管理端：<http://127.0.0.1:8910/web/admin.html>

从**仓库根**起服务的原因：页面用 `../barcode-demo/`、`../sync-demo/` 互链，且四个模块共用同源 localStorage 商品库 `bd_products`。如果只 `cd web` 起服务，互相跳转会 404，也读不到扫码台的数据。

### 方式 B：接 Go 后端（推荐）

```bash
cd /home/kiddyt00/GolandProjects/sdy/server
STATIC_DIR=.. go run ./cmd/server          # 默认 ADDR=127.0.0.1:8093
```

- 顾客端：<http://127.0.0.1:8093/web/index.html>
- 管理端：<http://127.0.0.1:8093/admin>（Go 给的干净地址，`/admin/` 会 301 到它；旧 `/web/admin.html`、`/admin.html` 仍可用）

（`STATIC_DIR` 是静态根目录，默认 `.` 只服务 `server/` 自己；指到 `..` 才能打开 `web/`、`barcode-demo/`、`sync-demo/` 的页面。）

Go 工具链不在默认 PATH 时，先导出环境（本机路径）：


页面启动时探测一次 `/healthz`（**只探测一次，不轮询**），命中就是 `server` 模式，否则 `local` 模式。地址来源按优先级：

## 设计要点与不变量

**数据与真源**

- **D12 单一真源**：页面不直连数据库、不持有任何密钥，全部请求走 `web/sdy-api.js`。服务端是规则与账目的唯一真源；服务端报错（如 409）**原样呈现给用户**，前端不自己改写结论。
- **在线/离线双模式**：`server` 模式下所有业务动作走后端接口（下单、流转、取消、改库存、建档、比价、条码解析）；`local` 模式下同一批动作落到 `Mall`/`Admin` 的本地实现。**同一套页面代码，两种模式都能用**。
- `server` 模式下前端只做展示与镜像：`SdyApi.sync()` 拉 `/api/products` 与 `/api/orders` 写回本地镜像，界面上看到的库存数字与后端一致。

**规则（前后端必须一致）**

- **配送规则**：自提 0 元；送货上门满 30 元免运费，否则 3 元（`DELIVERY_RULES = { pickupFee: 0, minFree: 30, fee: 3 }`）。
- **价格防护**：零售价 ≤ 牵牛花参考价 × 0.95（即 −5%），批发商品与无参考价（`refPrice <= 0`）自动跳过；同一套阈值也在后端 `internal/pricing` 里生效。
- **订单状态机**：`pending → delivering | ready → done`，且 `pending → cancelled`。`done`/`cancelled` 是终态，不允许再流转；非法流转服务端返回 409，前端照播后端文案。
- **下单与库存**：下单在一个事务里「校验 → 扣库存 → 写订单」，库存不足整单失败（不部分扣减）；取消订单**逐行回补库存**。本地模式同样是「先全量校验再扣减」。
- **D8 扫码只读**：顾客端「扫码找货」只做识别（先查本地商品档案，未建档再问后端解析链），**绝不改库存、不自动填价格**。

**商品档案（建档 / 编辑 / 删除）**

- **建档**：条码/货号必填（1–32 位数字、字母或 `._-`），商品名称必填且 ≤40 字；售价必须 > 0，进价/参考价非负，库存必须是非负整数；单位缺省「件」、分类缺省「未分类」。
- **编辑不改库存**：编辑弹窗根本不显示库存输入；在线模式下 `POST /api/products` **不带 `stock` 字段**，后端（`server/cmd/server/main.go`）用指针区分「没传」与「传 0」，没传就保留原库存。库存只能在「库存与流水」页进出。
- **初始库存**：新建时填了初始库存，本地模式会走一条 `stock_in` 流水（原因「建档初始库存」）并另记一条 `product_new` 档案流水；在线模式由后端写入。
- **删除两道闸**（与后端 `DELETE /api/products/{code}` 同规则）：① 库存必须为 0（提示「请先把库存盘点为 0 再删除」）；② 没有进行中（非 `done`/`cancelled`）的订单引用该商品。删档后 **`barcode_lib` 记录保留**（D6 永久沉淀），以后扫码仍能认出货名。
- **价格防线前置**：表单归一化时就跑 `Pricing.checkRetailPrice`（与 Go `internal/pricing` 同阈值），超价比价防线直接拦下并给出后端同款文案。
- **待同步标记**：任何档案变更都会把 `syncStatus` 置为「待同步」，提醒在下一次牵牛花月度对账时核对。

**商品图片、分类与上下架（任务池⑥ / D23）**

- **商品图存 URL，不存二进制**：`product.img` 只是一个字符串（图片地址），前端不做上传接口——家里人把图片丢进 `web/assets/demo/` 或任意能访问的图床，把地址填进建档/编辑弹窗的「商品图片地址」即可（两端空格自动裁掉）；这样后端零依赖、零存储、静态目录直接托管。管理端商品表第一列是 `thumb-wrap` 缩略图（40px 圆角 + 无图显分类 emoji + `object-fit:cover`），顾客端 `picHTML()` 渲染首页卡片图、`dimg` 渲染详情图、`cimg` 渲染购物车行图。
- **没图就回退 emoji**：`CAT_EMOJI` 按分类给默认图标（饮料 🥤 / 酒水 🍺 / 零食 🍪 …），`onerror` 兜底把裂图换成 emoji 占位，**所以老商品不填图也不会出现裂图**。
- **D23 上下架是独立动作**：建档/编辑表单里**没有**上下架开关，上下架只在商品表行尾的「下架 / 上架」按钮和批量面板里做，走 `POST /api/products/onsale`。**编辑档案不会偷偷上架或下架**（`saveProduct` 显式保留 `before.onSale`，与「编辑不改库存」同一条原则）。
- **下架只在顾客端生效**：下架后商品从顾客端列表消失、加购被拦、直接点开详情只提示「已下架」；**管理端一切照旧**——档案还在、库存照算、历史订单照打小票、条码字典照样能查，只是表格上多一个「已下架」灰标 + 缩略图变灰（`.thumb-wrap.off`）。
- **缺字段视为上架**：服务端 JSON 一律下发不带 `omitempty` 的 `onSale`，前端 `Mall.isOnSale(p)` 只在 `p.onSale === false` 时判为下架——**老库、老前端、老缓存都不会因为多一个字段就集体消失**。
- **分类不是独立表**：分类就是 `product.category` 上的一个字符串（缺省「未分类」），管理端顶部用 chip 列出各分类及**在售件数**（`chip-n`）；chip 上的 `×`（`chip-x`）是**改名/合并**入口——改名填成已有分类名就是合并（`renameCat` + `applyCatToCodes`），底层是逐个 `upsertProduct` 改 `category`。**合并后旧的空分类不会留下空壳**。
- **批量面板多了两排**：上排是原「批量改价」（比例/加减/统一 + 取整 + 按防线顶格），下排是「批量改分类」「批量改批发标记」和**「批量上下架」**（`#bulkOnSale` 上架/下架 + 应用到勾选商品）；所有批量动作**都不动库存**（D16），每款各记一条商品流水（原因如「批量下架」）。
- **⚠️ 批量写库必须带全字段**：`UpsertProduct` 的 UPDATE 含 `img = excluded.img`，所以**任何**在线 `SdyApi.upsertProduct({...})`（批量改价、批量改分类、批量改批发标记、建档/编辑）都必须带上 `img: p.img || ''`，否则会把已存图片抹成空串——这是第 18 轮真实踩过的坑。

**订单小票 / 配送单（打印）**

- **纯前端打印，零依赖**：不引任何打印库，靠 `#printRoot` + `@media print` 实现——屏幕上 `#printRoot` 是 `display:none`（不占位、不影响布局），打印时 `body > *` 全部隐藏、只显示 `#printRoot`，所以打到纸上的是**干净的小票**，不带侧边栏和按钮。
- **只读投影**：`Admin.buildReceipt(order, { store })` 是纯函数，只读订单与门店抬头，**不改订单、不改库存、不改价格**（与 D8 扫码只读同源）；同时返回结构化字段和一个 32 字宽纯文本版本（`r.text`，可复制给骑手）。
- **两种入口**：每张订单末尾的「🖨 小票」打单张；订单面板右上角「🖨 批量打印待备货」把所有 `pending` 订单一次排好（每张之间 `break-after: page` 分页，只唤起一次打印）。
- **票面内容**：店名/电话/地址（抬头）→ 单号/时间/状态/顾客/电话 → 配送单加地址与配送员（自提写「到店自提」）→ 逐行「名称 规格 / 单价 × 数量 = 金额」→ 件数/小计/配送费/应收 → 票尾。已取消的订单照打，但票面盖一行「已取消 / 作废」。
- **抬头在管理端「系统与工具 → 小票抬头」改**，存 localStorage `mall_store`；店名必填且 ≤20 字，票尾留空回落默认文案。抬头只影响本机打印，**不上后端**。
- **热敏尺寸**：`#receipt` 定宽 `72mm`（58mm 热敏纸可裁），`@page { margin: 6mm }`，一单一张不跨页。

**收货地址簿（D18）**

- **按手机号归档**：一个手机号一组常用地址，默认地址排最前、其余按入库顺序（`ORDER BY is_default DESC, id ASC`）。后端是 `customer_address` 表（`server/internal/store/store.go`），前端在 `localStorage.mall_addresses` 留一份镜像，离线时同一套语义照跑。
- **默认地址语义（两套实现必须一致）**：第一条保存的地址自动成为默认；显式勾「设为默认地址」时把同手机号其它条目的默认标记摘掉；**删掉默认地址后由最早的一条顶为默认**；编辑一条已有地址时不传默认标记就保留原来的标记（不会因为改门牌丢掉默认）。
- **结算时带出**：打开结算弹窗按当前手机号拉一次地址簿，默认地址直接回填收货人/手机号/地址，并在「常用地址（点一下带出）」里高亮选中项（品牌绿边框 + 浅绿底）；切换配送方式时刷新该区域，**自提不显示地址簿**；点某一条即回填表单。
- **下单时写入**：「保存到地址簿，下次一键带出」（默认勾选）勾上才会写；填的内容与带出的那条**完全一致就不重复写**，改了内容则存成**新的一条**（`id: 0`），**绝不覆盖已有地址**——想改已有地址走「地址簿管理」的编辑。写失败只 `console.warn`，不影响已经入库的订单。
- **地址簿管理弹窗**：顶部工具区「📍 地址簿」或结算弹窗里的「地址簿管理」都能打开；支持新增 / 编辑 / 设为默认 / 删除（删除有 `confirm` 二次确认）。
- **订单是快照**：订单里存的是下单当时的收货人/电话/地址，之后改地址簿**不影响历史订单**（与「小票只读投影」同一条原则）。
- **校验文案（前后端完全相同）**：`手机号不能为空`、`收货人不能为空`、`收货人不能超过 20 字`、`送货地址不能为空`、`送货地址不能超过 120 字`。

**销售报表 / 日报（D19）**

- **口径（家庭店视角）**：只统计**非取消订单**；营业额按**下单口径**（含还没送完的单）并另拆「已完成 / 进行中」——老板早上问的是「今天做了多少生意」，但没交付的钱也要单独看得见；商品金额取各单 `subtotal`（不含配送费），客单价 = 营业额 ÷ 单量。
- **六档区间**：`REPORT_RANGES = 今天 / 昨天 / 近 7 天 / 近 30 天 / 本月 / 全部`。按**本机时区**切自然日，区间含首尾；`全部` 以最早一单那天为起点，`本月` 从当月 1 号到今天，未知区间回落今天。
- **零单日也占一格**：日柱状图横轴是连续的日期序列，没生意的日子画一条 2px 的矮柱（`.rpt-bar.zero`），这样「哪几天没开张」一眼能看出来。柱高 = 当日营业额 ÷ 区间内最高日 × 100%，最少 2px。
- **只画该有的宽度**：柱少的时候不把图拉成整块——图表容器宽度取 `Math.max(240, Math.min(天数 × 60, 1136))px` 并居中；超过 12 天时日期标签隔两个抽一个、超过 20 天隔五个抽一个（完整日期在 `title` 里）。
- **环比**：跟**等长的上一个区间**比（今天比昨天、近 7 天比再往前 7 天），前一期为 0 或不可比（`全部`）时显示「—」，不编造百分比。
- **纯前端纯函数**：`Admin.buildReport(orders, key, now)` 与 `Admin.reportText(report, { store })` 只读订单与门店抬头，**不加后端接口**，离线（本地演示模式）也能出报表；页面只是渲染结果。
- **日报可带走**：`admin.html` 报表页右下角同时给出「📋 复制日报」和「🖨 打印日报」。复制优先用 `navigator.clipboard`，不可用（老浏览器 / 非安全上下文 / 假 DOM）时退回临时 `textarea` + `execCommand('copy')`，两种情况都只提示成功不抛错；打印复用 `#printRoot`（`<pre id="rptPrint">` + `@media print`），72mm 宽等宽字体，适合直连小票机或贴收银台。日报文本是 32 字宽纯文本，微信里粘贴不折行。
- **票面内容**：抬头「〈店名〉 · 销售日报」→ 区间 → 单量（含取消几单）→ 营业额（标注下单口径、不含取消）→ 客单价 → 商品金额 + 配送费 → 已完成 / 进行中 → 自提 / 配送单数 → 未完成三项计数 → 环比 → 热销 TOP5 → 生成时间。
- **KPI 数值不许换行**：报表页 8 张 KPI 卡里「已完成 / 进行中」「自提 / 配送」是**成对数值**（如 `¥0.00 / ¥0.00`），窄卡片里会被折成两行。`.kpi .k-value` 一律 `white-space: nowrap`，并按字符数自动降一档字号（`kpiSize()`：≤11 字默认 26px、≤17 字 `.sm` 19px、更长 `.xs` 15px），既保证留在同一行、又不撑破卡片；改 KPI 后必须在 1440 / 1024 / 760 / 420 四种宽度下用 CDP 回读 `lines === 1`、`scrollWidth ≤ clientWidth`、横向溢出为 0（见 `.agent_rules.md` 规则 13⑦）。

**批量改价 / 批量操作（D20）**

- **只碰这几样东西**：勾选一批商品后能改**售价**、**分类**、**批发标记**、**上下架**（上下架是第 18 轮商品表有了 `on_sale` 之后补的，走独立接口 `SdyApi.setOnSale`，见 D23）；**库存一律不动**（D16：库存只在「库存与流水」页进出）。
- **勾选跨筛选保留**：勾选状态存在 `bulkSel`（`code → 1`）而不是行 DOM 上，换关键词/分类后勾选不丢；表头复选框是全选/全清，面板标题里的计数是**当前筛选结果数**，不是勾选数。
- **改价三步**：先选规则——「按比例 %」/「按金额 ±元」/「统一设为元」，再选取整（不取整到分 / 到 1 角 / 到 5 角 / 到 1 元），快捷按钮给常用的 ＋10% / −10% / ＋1 元 / −1 元。
- **必须过比价防线**：预览逐款跑 `Pricing.checkRetailPrice`，结果分四种——`change`（可改）、`capped`（超防线，标红并显示「顶格 ¥x」）、`blocked`（新价非法，如设为 0）、`same`（价格没变，不写库）。**超线默认跳过不写**，想按防线价成交就点「按防线顶格」，把这几款的落地价改成 `round2(参考价 × 0.95)` 再一起应用。批发商品与缺牵牛花参考价（`refPrice <= 0`）的商品**跳过比价检查**，但照常改价、照常记流水（备注里写明原因）。
- **写库前逐款重读**：`applyBulkPlan` 不用页面上的旧快照写库，而是对每款先 `Mall.getProduct(code)` 拿**当前**商品，只覆盖要改的字段（改价只改 `salePrice`，改分类只改 `category`），这样别人刚改过的单位/库存不会被过期快照盖回去；当前价已经等于目标价的直接跳过（计 `noop`，不写流水）。
- **每款一条流水**：改价写 `edit` 流水、原因形如「批量改价：+10%」，改分类写「批量改分类：饮料」、改批发写「批量改批发标记：设为批发 / 取消批发」，方便在库存与流水页回溯是谁在什么时候动过价。
- **单款失败不连坐**：在线模式逐款 `await SdyApi.upsertProduct`（**请求体不含 `stock`**），某一款被后端拦下（例如取消批发后售价超防线）只记进失败清单，其余继续；结果区给出「成功 N / 跳过 N / 失败 N」和前几条失败原因，页面照常刷新。
- **在线离线同一套语义**：`server` 模式走 `SdyApi` 写后端（后端再跑一遍 `pricing.CheckRetailPrice`），`local` 模式走 `Admin.applyBulkPlan` / `Admin.applyBulkField`，两边规则与文案一致。


**约定与坑**

- **localStorage 键**：`bd_products`（商品库，与扫码台、对账工具**同源共用**）、`mall_cart`（购物车）、`mall_orders`（订单）、`mall_customer`（上次填写的收货信息）、`mall_addresses`（收货地址簿镜像）、`mall_couriers`（配送员名单）、`mall_stockLog`（库存流水，上限 500 条）、`mall_customers`（顾客备注）、`mall_store`（小票抬头：店名/电话/地址/票尾）、`sdy_api_base`（后端地址）。
- **跨模块共用**：商城、扫码台、对账工作台必须用**同一个端口（同一源）**打开，才看到同一份 `bd_products`。
- **历史坑（已修，勿回退）**：`mall.js` 在浏览器里声明了顶层 `const Mall`，`mall-admin.js` 若再声明一个 `Mall` 会直接 `SyntaxError: Identifier 'Mall' has already been declared`，导致整个后台脚本静默失效。所以后台注入时用的是 `MallCore` 这个名字，别改回去。
- **假 DOM 测试的坑**：`web/test-page-boot.js` 里的 `env.els.X` **只在页面脚本调用过 `getElementById('X')` 之后才存在**——测试要用到的元素，要么先驱动页面走到会碰它的那一步，要么自己 `env.els.X = fakeEl('X')`；页面脚本用到的浏览器弹窗（`confirm` / `prompt`，分类改名就用 `prompt`）必须在沙箱里注入，`makeEnv` 已给 `prompt` 默认 `() => null`，需要返回值时按测试传参。
- **库存页形态未定稿**：`web/mall-admin.js` 顶部注释写明库存页是**占位实现**（D1/D2/D4 待确认后可能调整），改动前先看 `../细节讨论记录.html`。
- **顾客端不做摄像头扫码**：顾客端只有扫码枪/手动输入（`扫码找货` 弹窗），摄像头那条路在扫码台里。
- 商品搜索：顾客端匹配 `名称 + 品牌 + 条码`；后端 `ListProducts` 的 `keyword` 只匹配 `名称 + 条码`（不含品牌）。两边口径不同，是已知差异。
