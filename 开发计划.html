独立小程序商城 · 开发计划 v1

版本 v12026-10-10 依据：架构方案 + 细节讨论记录（D1–D8）
一句话路线：页面展示优先 → 规则与数据层 → 牵牛花同步 → 后端服务 → 小程序化 → 上线验证。 先让「看得见」的页面把全流程跑通（web demo 先行），再逐层填充真实逻辑与后端，降低返工、随时可演示给合伙人看。

一、目标与边界

维度内容
总目标自营微信小程序商城，完全独立于牵牛花中台：商品、价格、库存、订单、配送、顾客全部自管理；与牵牛花仅保留月度 CSV 库存同步
MVP 范围常温商品 + 酒水饮料；生鲜后置（P1+）；固定客群私域沉淀；自提免配送费 + 4 人配送
红线敏感信息绝不上库；扫码只读不改库存（D8）；建档必须人工确认；价格/库存永不自动填云端值；云端调用仅双库未命中（D6）；先不买枪、手机摄像头验证（D7）
技术形态web demo（纯 HTML/JS + localStorage，无构建）先行；后端 Go（1.24，标准库 net/http + SQLite）；最终小程序端复用 demo 页面设计

项内容
数据模型product / barcode_lib / order / order_item / customer / sync_batch

2026-10 用户决定：后端语言由 Python 改为 Golang——与生产服务器上同机的 yiguan 项目（Go）同栈，Docker 蓝绿部署范式可直接复用；静态单文件部署无需运行时依赖；并发处理条码代理/订单请求更省心。
部署生产服务器（IP 见本地 .server_cred.md，公开文档不披露）（Ubuntu / 4 核 / 3.7G 内存 / 40G 盘 / Docker 29 + Compose v5），参照同机 yiguan 项目范式：
• Docker Compose 部署，镜像拉取走国内代理 docker.1ms.run/library；
• 蓝绿 A/B 双实例（frontend-a / frontend-b）滚动更新，主机级 Nginx upstream 池做反代与失败重试；
• 主机 Nginx 继续监听 80/443（现有服务在用），本项目只新增一个域名 conf，证书用现成 acme.sh；
• 端口约定：前端 8091 / 8092（蓝绿），后端 8093，均绑 127.0.0.1；已占用端口一律避开：22 / 53 / 80 / 443 / 8081 / 8082（yiguan 前端）；
• 服务器上还有其他在跑的服务，改动前先 ss -tlnp + docker ps 复核，不动他人配置。

十一、风险与红线

风险：① 牵牛花导出能力未知 → 行动项 0 尽快验证；② 小程序/商户号申请周期 → 提前并行申请；③ 配送 API 成本与权限 → 自提优先、配送后置；④ 一码多品 → 建档人工确认。
红线：敏感信息（AppCode/凭证/Token）绝不入库，每次推送前三层扫描；扫码只读（D8）；价格与库存永不自动填云端值；建档必须人工确认；腾讯文档推送前必须 pull 比对、保留外部修改。
