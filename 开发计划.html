一句话路线：页面展示优先 → 规则与数据层 → 牵牛花对账 → 后端服务 → Web 端商城现代化与功能实现（当前） → 小程序化（暂缓） → 上线验证。 先让「看得见」的页面把全流程跑通，再逐层填真实逻辑与后端，降低返工、随时可演示给合伙人看。

一、目标与边界

维度内容
总目标自营商城，完全独立于牵牛花中台：商品、价格、库存、订单、配送、顾客全部自管理；与牵牛花仅保留月度 CSV 库存对账
MVP 范围常温商品 + 酒水饮料；生鲜后置（P1+）；固定客群私域沉淀；自提免配送费 + 4 人配送
形态与技术栈前端：纯 HTML/JS + 一个共享设计系统（web/assets/theme.css），无构建步骤、无 npm 依赖；后端：Go 1.24 + 标准库 net/http + SQLite（modernc.org/sqlite 纯 Go，CGO_ENABLED=0 静态单文件）；小程序端（暂缓）复用同一套视觉令牌
红线敏感信息绝不上库；扫码只读不改库存（D8）；建档必须人工确认；价格/库存永不自动填云端值；云端调用仅双库未命中（D6）；先不买扫码枪、手机摄像头验证（D7）

八、风险与红线

风险：① 牵牛花导出能力未知 → 行动项 0 尽快验证；② 域名备案周期长 → 现在就可启动；③ 小程序账号/商户号审批周期 → 若要做就并行申请；④ 配送 API 成本与权限 → 自提优先、配送后置；⑤ 一码多品/无条码商品 → 建档必须人工确认；⑥ 家庭店人力有限 → 管理端操作要尽量少点击（库存三操作、批量改价、小票打印优先）。
