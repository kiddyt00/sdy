独立小程序商城 · 开发计划 v1

版本 v12026-10-10 依据：架构方案 + 细节讨论记录（D1–D8）
一句话路线：页面展示优先 → 规则与数据层 → 牵牛花同步 → 后端服务 → 小程序化 → 上线验证。 先让「看得见」的页面把全流程跑通（web demo 先行），再逐层填充真实逻辑与后端，降低返工、随时可演示给合伙人看。

一、目标与边界

维度内容
总目标自营微信小程序商城，完全独立于牵牛花中台：商品、价格、库存、订单、配送、顾客全部自管理；与牵牛花仅保留月度 CSV 库存同步
MVP 范围常温商品 + 酒水饮料；生鲜后置（P1+）；固定客群私域沉淀；自提免配送费 + 4 人配送
红线敏感信息绝不上库；扫码只读不改库存（D8）；建档必须人工确认；价格/库存永不自动填云端值；云端调用仅双库未命中（D6）；先不买枪、手机摄像头验证（D7）
技术形态web demo（纯 HTML/JS + localStorage，无构建）先行；后端 Python 标准库服务；最终小程序端复用 demo 页面设计

十一、风险与红线

风险：① 牵牛花导出能力未知 → 行动项 0 尽快验证；② 小程序/商户号申请周期 → 提前并行申请；③ 配送 API 成本与权限 → 自提优先、配送后置；④ 一码多品 → 建档人工确认。
红线：敏感信息（AppCode/凭证/Token）绝不入库，每次推送前三层扫描；扫码只读（D8）；价格与库存永不自动填云端值；建档必须人工确认；腾讯文档推送前必须 pull 比对、保留外部修改。
